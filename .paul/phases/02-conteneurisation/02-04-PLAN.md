<task type="auto">
  <name>Task 1: docker-compose.yml + .env.example mis à jour</name>
  <files>docker-compose.yml, .env.example</files>
  <action>
    docker-compose.yml :

    version: "3.9"

    services:
      db:
        image: postgres:16-alpine
        container_name: forum-db
        environment:
          POSTGRES_USER: ${POSTGRES_USER}
          POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
          POSTGRES_DB: ${POSTGRES_DB}
        volumes:
          - postgres-data:/var/lib/postgresql/data
        networks:
          - forum-network
        healthcheck:
          test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
          interval: 5s
          timeout: 5s
          retries: 10

      api:
        build: .
        container_name: forum-api
        environment:
          DATABASE_URL: postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@db:5432/${POSTGRES_DB}
          SECRET_KEY: ${SECRET_KEY}
          PORT: ${PORT:-8000}
        ports:
          - "${PORT:-8000}:${PORT:-8000}"
        depends_on:
          db:
            condition: service_healthy
        networks:
          - forum-network
        command: >
          sh -c "alembic upgrade head && uvicorn src.main:app --host 0.0.0.0 --port ${PORT:-8000}"

    volumes:
      postgres-data:

    networks:
      forum-network:
        driver: bridge

    Règles :
    - Aucune valeur réelle dans le fichier — uniquement ${VAR} ou ${VAR:-default}
    - La DB doit être healthy avant que l'API démarre (depends_on condition: service_healthy)
    - Les migrations Alembic s'exécutent au démarrage de l'api via `alembic upgrade head`
    - Le réseau s'appelle forum-network (bridge)
    - Le volume postgres-data persiste les données entre redémarrages

    .env.example — ajouter les variables PostgreSQL manquantes :
    DATABASE_URL=postgresql://user:password@localhost:5432/forum
    SECRET_KEY=changeme
    PORT=8000
    POSTGRES_USER=forum_user
    POSTGRES_PASSWORD=forum_password
    POSTGRES_DB=forum
  </action>

  <done>AC-1 et AC-4 partiellement satisfaits : docker-compose.yml valide syntaxiquement, aucun secret en clair</done>
