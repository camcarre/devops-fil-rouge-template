## Goal
Produire un script de démo reproductible + checklist pré-soutenance qui permettent à n'importe quel membre de l'équipe de piloter la démo bout-en-bout sans improviser.

La soutenance réussit ou échoue sur la démo live. Ce plan fixe les étapes, le timing, les responsabilités et les fallbacks — tout ce qui doit être su à l'avance.

`docs/demo-script.md` — script de démo complet + checklist pré-soutenance

## AC-1 : Script de démo complet
Given le fichier `docs/demo-script.md` existe
When un membre de l'équipe le lit
Then il dispose de : (1) séquence d'étapes numérotées couvrant docker-compose ET K8s, (2) timing estimé par étape (≤ 15 min total), (3) rôle assigné par étape (qui parle / qui tape), (4) commandes exactes à copier-coller, (5) vérification attendue après chaque étape clé

## AC-2 : Fallbacks documentés
Given le script
When une étape échoue en direct
Then au moins 3 fallbacks critiques sont documentés (ex : `docker-compose up` lent → image pré-pull ; minikube crash → rollback compose ; pod CrashLoopBackOff → kubectl describe logs)

## AC-3 : Checklist pré-soutenance
Given la section checklist du script
When l'équipe la parcourt la veille de la soutenance
Then elle couvre : env local prêt (minikube up, images build), secrets K8s appliqués, Prometheus + Grafana accessibles, README visible sur GitHub, chaque membre connaît son rôle
</acceptance_criteria>

Créer `docs/demo-script.md` avec :

### Structure attendue

**Header** : date soutenance (placeholder), durée totale cible (≤15 min), membres + rôles

**Partie 1 — docker-compose (≈4 min)**
- Étape 1 : `docker-compose up --build` → vérifier `api` healthy + `db` healthy
- Étape 2 : smoke test API — `curl http://localhost:8000/healthz` + `curl http://localhost:8000/categories`
- Étape 3 : montrer logs (`docker-compose logs api | tail -20`)
- Timing estimé, qui tape / qui parle

**Partie 2 — Kubernetes (≈7 min)**
- Étape 4 : `minikube start` (si pas déjà up) + `kubectl get nodes`
- Étape 5 : load image → `minikube image load forum-api:latest`
- Étape 6 : apply manifests → `kubectl apply -f k8s/` + rollout status
- Étape 7 : accès API (minikube tunnel OU port-forward) + curl /healthz
- Étape 8 : Prometheus → port-forward 9090, montrer target forum-api UP
- Étape 9 : Grafana → port-forward 3000, ouvrir dashboard

**Partie 3 — CI (≈2 min)**
- Étape 10 : ouvrir GitHub Actions, montrer dernier run vert + badge README

**Fallbacks (section dédiée)**
- docker-compose lent → `docker-compose pull` la veille, images déjà en local
- minikube OOM → `minikube stop && minikube delete && minikube start --memory=4g`
- Pod CrashLoopBackOff → `kubectl describe pod <name>` + `kubectl logs <name> --previous`
- Grafana inaccessible → montrer capture d'écran préparée dans `docs/`

**Checklist pré-soutenance (checkbox markdown)**
- [ ] `docker-compose up --build` fonctionne en local (test la veille)
- [ ] `minikube start` + `kubectl apply -f k8s/` → tous pods Running
- [ ] Secret K8s appliqué (`kubectl get secret forum-secret`)
- [ ] Prometheus : target `forum-api` = UP
- [ ] Grafana : dashboard visible, données présentes
- [ ] `curl /healthz` + `/categories` → 200
- [ ] Badge CI vert sur GitHub
- [ ] README pointe sur bon dépôt (URL correcte)
- [ ] Chaque membre a répété son segment (voir rôles dans le script)
- [ ] Laptop branché secteur, mode veille désactivé
